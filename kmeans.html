Part 1 · Clustering · Centroid-based

K-means, one step at a time.

K-means splits the data into \(K\) groups, where \(K\) is a number you choose. It is simple, fast, and usually the first clustering method people try. Here you will drag centroids yourself, watch the algorithm run, see it get stuck, and learn how to choose \(K\).

01The idea

Choose a number \(K\), for example \(K = 3\): "give me three groups". K-means then follows two rules:

  1. Every point is in some cluster. Nobody is left out.
  2. No point is in two clusters at once.

Together: every point is in exactly one cluster. Mathematically, the clusters \(C_1, \dots, C_K\) form a partition of the data:

$$C_1 \cup C_2 \cup \dots \cup C_K = \{1, \dots, n\} \qquad C_k \cap C_{k'} = \varnothing \ \text{ for } k \neq k'$$

02What makes a good clustering?

We want each cluster to be tight: its points close to each other. K-means gives that idea a number, the within-cluster variation \(W(C_k)\). Big \(W\) means a loose, messy cluster; small \(W\) means a tight one.

$$W(C_k) = \frac{1}{|C_k|} \sum_{i, i' \in C_k} \sum_{j=1}^{p} \left(x_{ij} - x_{i'j}\right)^2$$
\(C_k\)
the \(k\)-th cluster: the set of points assigned to it
\(|C_k|\)
how many points are in cluster \(k\) (the bars mean "size of the set")
\(i,\ i'\)
any two points in the same cluster
\(\sum_j (x_{ij} - x_{i'j})^2\)
squared Euclidean distance between them, over all \(p\) features

So: take every pair of points in the cluster, add up their squared distances, and divide by the cluster size. K-means looks for the clusters that make the total as small as possible:

$$\underset{C_1, \dots, C_K}{\text{minimize}} \ \left\{ \sum_{k=1}^{K} W(C_k) \right\}$$
Link to regression

In regression we minimised the sum of squared residuals. Here we minimise a sum of squared distances inside clusters. Same idea, new use. And again we square so that distances never cancel.

Be the algorithm

Drag the ✕ centroids. Each point joins its nearest centroid. Make the total W as small as you can.

Why does the centroid appear if the formula only uses pairs? dive deeper

A neat identity links the pairwise formula to the distance from each point to its cluster mean \(\bar{x}_{k}\) (the centroid):

$$\frac{1}{|C_k|}\sum_{i,i' \in C_k}\sum_{j=1}^{p}(x_{ij}-x_{i'j})^2 \;=\; 2\sum_{i\in C_k}\sum_{j=1}^{p}(x_{ij}-\bar{x}_{kj})^2$$

So minimising \(W\) is the same as minimising the squared distance of every point to its own centroid. That is why the algorithm below works with centroids, and why scikit-learn reports inertia_: the right-hand sum without the factor 2. In this lab, "total W" uses the lecture's pairwise formula (so it equals 2 × inertia).

03Why not try every split?

Why not test every possible way to split the points and keep the best? Because the number of splits explodes. Move the sliders.

Counting the ways

Brute force is hopeless beyond a handful of points.

So we use a smart shortcut: an iterative algorithm that improves the clusters step by step. It is fast, but it finds a local minimum: a good answer, not always the best possible one.

04The algorithm, step by step

K-means has only two moves, repeated until nothing changes:

step 1 · start

Random assignment

Give every point a random cluster number from 1 to K.

step 2a · update

Compute centroids

For each cluster, the centroid is the average point. Points (2, 4) and (4, 6) have centroid (3, 5).

step 2b · assign

Join the nearest

Every point looks at all centroids and joins the nearest one. Repeat 2a and 2b until no point changes cluster.

Quick check

A cluster has points (1, 1), (3, 1) and (2, 4). What is its centroid? Average each coordinate: ((1+3+2)/3, (1+1+4)/3) = (2, 2).

Why is K-means guaranteed to stop? dive deeper

Each move can only lower the objective or leave it unchanged. In step 2a, the mean is the point that minimises the sum of squared distances to a set of points, so moving the centroid there cannot increase it. In step 2b, moving a point to a nearer centroid also cannot increase it. Since there is a finite number of possible partitions and the objective never goes up, the algorithm must stop. Watch the objective chart in the stepper: it never rises.

05Local minima: run it many times

Good news: each step lowers the objective, so K-means always stops. Bad news: it stops at a local minimum that depends on the random start. Below are six runs on the same data with different random starts. The number above each is the objective. Lower is better.

Six random starts

In practice

Run K-means many times and keep the run with the smallest objective. scikit-learn does this for you with n_init (10 random starts by default with random init).

06Choosing K

K-means needs \(K\) before it starts, but in real problems nobody tells us how many groups there are. Two common tools help:

  • Elbow method. Run K = 1, 2, 3, … and plot the objective. It always falls as K grows (more centroids, tighter clusters), so look for the elbow: where it stops dropping fast.
  • Silhouette score. For each point, compare \(a\) = its average distance to its own cluster with \(b\) = its average distance to the nearest other cluster: \(s = (b - a)/\max(a, b)\). Near 1: well placed. Near 0: on a border. Negative: probably in the wrong cluster. Pick the K with the highest average.

Elbow and silhouette

Click a K on either chart to see that clustering.

Elbow: total within-cluster variation vs K

Silhouette: average score vs K (higher is better)

Be honest

Neither tool is a proof. On "no structure" data the silhouette still picks some K, and K-means happily returns clusters. Always ask whether the groups make sense to someone who knows the domain.

07Scale your features first

K-means uses plain Euclidean distance, so a feature measured in big numbers dominates. Here, monthly income is in Bahraini dinars (hundreds to thousands) and age is in years (tens). Without scaling, income decides everything.

Customers: income vs age

Same data, same K = 4. Only the scaling changes.

Standardising means: subtract each column's mean and divide by its standard deviation, \(z = (x - \bar{x}) / s\). Every column then has mean 0 and spread 1, so each feature gets a fair vote. In scikit-learn: StandardScaler before KMeans.

08Where K-means fails

K-means assigns every point to its nearest centre, so it always carves the space into straight-edged regions around centres. That works for round, similar-sized blobs and fails for curved, stretched or nested shapes. Remember the two moons?

K-means on six kinds of data

Best of 10 starts each, with the true number of groups as K.

For curved shapes, try single-linkage hierarchical clustering or DBSCAN. For stretched blobs, try Gaussian mixtures.

09Smarter starts: K-means++

Bad starts cause bad local minima. K-means++ chooses starting centroids that are spread out: the first is a random point; each next one is chosen at random with probability proportional to \(D(x)^2\), the squared distance to the nearest centroid already chosen. Far-away points are much more likely to be picked. It is the default in scikit-learn (init="k-means++").

11Pros and cons

Pros

  • Very simple to understand and explain
  • Very fast, even for large data
  • Always converges
  • Centroids are easy to interpret ("the average customer of group 2")

Cons

  • Results change with the random start: run it many times
  • Needs scaled features; prefers round, similar-sized clusters
  • You must choose K yourself
  • Every point is forced into a cluster, even outliers
